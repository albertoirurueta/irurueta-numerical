# Implementation Plan: Fix existing PMD violations (Issue #40)

## 1. Task summary

Source: GitHub issue #40
Base branch: develop

`mvn clean compile pmd:pmd` on `develop` (1.8.0-SNAPSHOT, `src/main`, JDK 21) reports **35** PMD violations:
UselessParentheses 23, EmptyCatchBlock 11, UnnecessaryModifier 1 (re-measured while planning, identical to the issue).
The work removes all of them with no production behavior change.

Choices made on the user's behalf (challenge during review):
- Target is **0 violations**, with no suppressions (`@SuppressWarnings`, `// NOPMD`) and no custom PMD ruleset.
- `EmptyCatchBlock`: PMD's default `allowExceptionNameRegex` is `^(ignored|expected)$`, and today's blocks use
  `ignore` or `e`. Renaming the catch parameter to `ignored` (keeping the existing explanatory comment) clears the
  rule without changing behavior. No logging or rethrow is added: these are "never happens" paths, or deliberately
  swallowed failures in the robust estimators ("if anything fails, no solution is added").
- `UnnecessaryModifier` (`BuildInfo.java:129`): drop the redundant `final` on the try-with-resources variable.
- PMD stays report-only: no `failOnViolation` gate and no `<build>` plugin binding (same stance as the Checkstyle
  work in #39). The result is documented in `CLAUDE.md`.
- `src/main/resources/.../build-info.properties` is regenerated by every Maven build; it must be restored
  (`git checkout`) before committing, never committed as part of this change.
- Maven needs JDK 21 (`JAVA_HOME=$(/usr/libexec/java_home -v 21)`); the default `java` here is 17.

Open clarifications: none
