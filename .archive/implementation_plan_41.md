# Implementation Plan: Fix or triage existing SpotBugs findings (Issue #41)

## 1. Task summary

Source: GitHub issue #41
Base branch: develop

`mvn clean compile spotbugs:spotbugs` on `develop` (1.8.0-SNAPSHOT, `src/main`, JDK 21) reports **264** findings
(re-measured while planning, identical to the issue): CT_CONSTRUCTOR_THROW 118, EI_EXPOSE_REP 75, EI_EXPOSE_REP2 53,
REC_CATCH_EXCEPTION 6, DE_MIGHT_IGNORE 5, FE_FLOATING_POINT_EQUALITY 4, IM_AVERAGE_COMPUTATION_COULD_OVERFLOW 2,
AT_STALE_THREAD_WRITE_OF_PRIMITIVE 1. The work reviews the 18 correctness-type findings (fixing the real bugs) and
triages the 246 design-level findings through a documented SpotBugs exclude filter, so that `mvn spotbugs:spotbugs`
reports 0 unfiltered findings.

Choices made on the user's behalf (challenge during review):
- **Real fixes** (no behavior change): make `RobustEstimator.progressDelta` `volatile` (AT_STALE_THREAD_WRITE) and
  replace `(ju + jl) >> 1` with `(ju + jl) >>> 1` in `BaseInterpolator` (IM_AVERAGE_COMPUTATION_COULD_OVERFLOW).
- **Design-level findings are excluded, not fixed**: `CT_CONSTRUCTOR_THROW`, `EI_EXPOSE_REP` and `EI_EXPOSE_REP2` come
  from the library's design (validating constructors throw; arrays/matrices are shared on purpose for performance and
  are part of the public API contract). Making ~hundreds of classes `final` or copying defensively would be a breaking
  API/performance change. They are excluded project-wide **by bug type** in `spotbugs-exclude.xml`, each with a
  rationale comment. No `@SuppressFBWarnings` annotations are added (no new dependency on spotbugs-annotations).
- **Floating-point equality (4) and catch-all/ignored-exception sites (6 + 5)** are reviewed individually. Where the
  behavior is intentional (Numerical-Recipes-style exact comparisons of values copied from one another; the "if
  anything fails, no solution is added" robust-estimator listeners) the finding is excluded with a **class-scoped**
  `<Match>` and rationale, not a global exclusion; otherwise the code is fixed. The rule: never change numerical results
  or swallow-vs-propagate semantics just to silence the tool.
- SpotBugs stays **report-only**, like PMD (#40) and Checkstyle (#39): the filter is configured on the plugin in
  `pom.xml` (so `mvn spotbugs:spotbugs` and the site report use it), but no `check` goal is bound to the build and
  `failOnError` is not enabled.
- `src/main/resources/.../build-info.properties` is regenerated by every Maven build; restore it (`git checkout`)
  before committing, never commit it.
- Maven needs JDK 21 (`JAVA_HOME=$(/usr/libexec/java_home -v 21)`); the default `java` here is 17.

Open clarifications: none
